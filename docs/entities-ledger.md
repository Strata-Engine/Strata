Task 1: Ruling: an id is (generation << 20) | row, the row in the low 20 bits (capacity is at most 2^20) and the generation in 1..2^31-1 above it, wrapping to 1; en_remove raises the row's generation, so every id is positive (-1 is free for "none") and an old id stops matching its row at once — the design leaves the packing to the builder — a row removed 2^31 - 1 times hands an old id's generation out again.
Task 1: Ruling: the columns are one array per column, capacity rows long, a row keeping its index for its whole life: kind (int16, -1 free), generation (uint32), the row's index in its kind's dense array (int32), position (3 doubles, metres), velocity (3 floats), facing (float, radians), age (double, seconds), float slots (8 floats a row), int slots (8 int64 a row), parts (4 int64 a row: figure, body, voice 0, voice 1, -1 none) — positions need a double (an island 2 km across at 10 cm voxels) and the age accumulates dt; fixed 8-slot strides keep a row's slots at a computed offset — about 185 bytes a row: 12 MB at the default 65,536 rows, 195 MB at 1,048,576, plus the kinds' dense arrays (below); later columns (state, route, grid cell) are further arrays of the same shape.
Task 1: Ruling: each kind keeps a dense array of its live rows' numbers (capacity entries a kind, 62 x capacity int32 in one calloc) and each row its index in that array; an add appends, a remove moves the kind's last entry into the hole; en_each, en_column, en_set_column and en_hash walk these arrays in order, so a walk is a sequential pass costing what the kind holds and never touching a dead row or another kind's; en_each order is "dense order": add order until a removal, after which the kind's last entity takes the removed one's place (deterministic for a given call sequence) — review finding: the first build's per-kind linked list made every step of a walk wait on the previous load, and after reuse visited rows at scattered indices; the controller ruled for a dense array, rows staying where they are — the dense arrays reserve 16 MB at 65,536 rows and 260 MB at 1,048,576 of address space, but calloc'd pages a kind never reaches stay unmapped, so resident memory is about 4 bytes a live entity; the columns themselves are still read by row, so a walk's column reads scatter as rows are reused.
Task 1: Ruling: free rows are a stack, row 0 handed out first and the last freed row reused first — none — a stale id's row is very likely live again with another generation, which is what the stale-id test exercises.
Task 1: Ruling: a kind registers a body only with the Body mover and the Body mover only with a body (EN_R_BODY either way), as design section 3 refuses "any other combination" — none.
Task 1: Ruling: a kind's half extents and step height must be finite and >= 0, its lifetime and gravity finite, its seen distance finite and at most the world's seen cap compared as a float (so a kind passing the cap itself, e.g. 100.3, is accepted; refused above it, EN_R_VALUE); a seen distance <= 0 is stored as the seen cap, so en_kind_float(kind, 5) reads the distance in force — the design calls the seen cap "the most allowed" — a game that opens a world with a smaller seen cap must lower its kinds' distances.
Task 1: Ruling: en_set which 2 (facing) reads v[0]; which 3 (age) is the kernel's and is refused (EN_R_WHICH) and counted — controller ruling (a).
Task 1: Ruling: en_kind_int(kind, which) and en_kind_float(kind, which) read a kind's ints and floats in en_kind's order (-1 and 0 for no such kind or field) — controller ruling (b), so later tasks read has-figure, has-body and voices.
Task 1: Ruling: en_open checks route_points and bodies (1..1,048,576) and seen_cap, chunk_metres and voxel_metres (finite and > 0) and keeps them, returning NULL for any out of range; nothing else uses them yet — controller ruling (c).
Task 1: Ruling: en_set_part refuses a part the kind lacks (a figure on a kind without one, a body without one, a voice past its voice count; EN_R_PART) and an id below -1 (EN_R_VALUE) — none.
Task 1: Ruling: velocity, facing and float slots are floats: a value finite as a double but beyond a float's range is refused (EN_R_VALUE), never stored as an infinity — none.
Task 1: Ruling: reads are const and are not counted: a dead id reads defaults and en_get returns 0; an en_get of no such field returns 0 and leaves out untouched; en_each and en_column return the rows written (at most max), so a caller learns a kind's live count by passing max = capacity — none.
Task 1: Ruling: en_set_column checks every value is finite before writing any, so a refused column writes nothing — none.
Task 1: Ruling: en_hash runs kind by kind in en_each order over each live row's id, kind, position, velocity, facing, age, the kind's float and int slots and the parts; routes join it in the route task — none.
Task 1: Ruling: en_stat 1, 2, 4, 5 and 7 (seen, waiting for ground, negative dt, events dropped, over the body budget) read 0 until the tasks that tick, see and drop exist — none.
Task 2: Ruling: `Strata.Entities.Kind` is a record whose fields carry an `en_` prefix (en_mover, en_unseen, en_divisor, en_fslots, en_islots, en_hx, en_hy, en_hz, en_step, en_gravity, en_lifetime, en_seen), and `Entities` is { en_kinds, en_bodies, en_live } — controller ruling (d): names unique across the program (GAPS S18, S19), and a record of mixed Ints and Floats is not the all-Float single constructor of S23 — the figure, body and voice fields come with their `with_` functions in Tasks 7 and 8; until then the kernel is sent 0 for them.
Task 2: Ruling: a kind's gravity is one Float (m/s2) in March; the kernel's gravity flag is sent as 1 when it is not 0 — `with_mover` takes gravity as a Float — a kind cannot ask for gravity 0 with the flag on, which means nothing anyway.
Task 2: Ruling: `valid` checks what en_kind checks that needs no world (mover 0..2 for now, unseen 0..2, divisor >= 1, slots 0..8, every float finite as a 32-bit float, half extents and step height >= 0) and also refuses a walking kind with any half extent 0, which the kernel accepts; `open` runs `valid` on each kind before sending it, so such a kind makes the world not open — the brief's Step 1 test — a bodied kind (mover 3) is invalid until Task 8's body functions exist, as the kernel refuses a Body mover without a body; the seen distance against the seen cap is checked only by the kernel at `open`.
Task 2: Ruling: `open` treats capacity <= 0 as 65,536 and bodies <= 0 as 128 (the design's defaults), passes 262,144 route points, and sends the seen cap (radius_h - 2) x chunk_metres, at least one chunk_metres; a capacity above 1,048,576 is not clamped but refused (not open); if any kind is refused the kernel world is closed again, so `is_open` false means no world at all — controller ruling (a) for capacity; bodies by analogy — none.
Task 2: Ruling: every Strata.Entities call checks the value's open flag before calling C, so a call on a closed (or never opened) `Entities` does nothing and answers the defaults even while another world is open; the C wrapper also answers defaults with no world — the `closed` scene — one world per process: an `Entities` value still marked open after another `open` addresses the newer world.
Task 2: Ruling: an id crosses as an Int (the kernel's int64, at most 2^51), -1 for none; `each` asks the kernel for the kind's live count (en_x_count), allocates a NativeIntArr of exactly that many, and en_x_each fills it (8 bytes an element at +32, as the runtime lays out NativeIntArr); `column` does the same with en_x_column_width x count floats — controller ruling (c); the constraints list NativeIntArr's narrower cousins but ids need 64 bits — a NativeIntArr is written by C, like the NativeF32Arr anim's matrices are.
Task 2: Ruling: en_x_set_column takes the rows from the array's length (length / width) and refuses a length that is not a whole number of rows as EN_R_ROWS; the kernel refuses rows other than the kind's live count — none.
Task 2: Ruling: three-number reads come back one number a call (en_x_get(id, which, k)), as anim's marks do; `position` and `velocity` are three calls, each finding the row again — no caller-owned array for a single entity — a per-entity read in a hot loop costs three lookups; whole kinds should use `column`.
Task 2: Ruling: the determinism scene ports the Task 1 script (the same LCG, 1,000 steps, capacity 256) to March; adds outnumber removes, so the world fills and later adds are refused (85 of them), as in the C test; the scene checks both runs refuse the same count rather than none — C argument order is unspecified, so March's draws need not match C's call for call — the March hash is not compared with the C test's.
Task 3: Ruling: the kernel holds each chunk in an open-addressing table keyed by chunk coordinates (1,024 slots at open, doubled when live plus deleted slots pass half, rehashed in place when deleted slots dominate); a chunk all clear or all solid is held as a state with no mask, any other as a 4,096-byte mask in Strata.Occupancy's bit layout, allocated as it arrives and freed when dropped or replaced — the design's "4 KB a loaded chunk" — so strata_ent.h's "nothing allocates after en_open" now excepts the masks and the chunk table; a chunk coordinate beyond ±2^25 is refused (its voxels must fit an int).
Task 3: Ruling: en_block_table takes a byte an id (at most 65,536); ids past n and ids outside 0..65535 in a chunk pass; the table is not applied to chunks already held (their ids are not kept), so `Strata.Entities` sends it before any chunk, once, on the first `blocks` or `blocks_world` (flag `en_table` in `Entities`) — brief Step 3 — a registry that changes after that is not resent.
Task 3: Ruling: en_ray mirrors Strata.Query.raycast's walk operation for operation in doubles (unit direction, voxel units, first crossings, `t > tmax` before each voxel, the step budget 3 * floor(tmax) + 8, the start-inside face facing back along the strongest axis), under `#pragma STDC FP_CONTRACT OFF` so ties break as in March; entering a voxel whose chunk is not held answers -1 (-2.0 through en_x_ray), where Strata.Query reads air and walks on — the ray scene keeps its held chunks a box, so a ray that leaves cannot come back and -2.0 always pairs with a Strata.Query miss — 573 of 2,000 rays hit (155 on pillars), 479 miss, 948 leave the box.
Task 3: Ruling: a seen flyer whose ray answers -1 (it would leave the held chunks) moves its whole step, as if nothing were there — controller ruling (g) leaves the not-loaded hold to Task 6 — a seen flyer can fly into a chunk not yet generated; Task 6's "held where it is" rule may replace this.
Task 3: Ruling: a flyer stopped by a block is put at the hit point (o + unit(v) t), its velocity 0, and flagged (EN_F_STUCK in a new per-row flags byte); a stuck flyer is not moved again (no gravity, no ray, no further event 2) until the game sets its position or velocity (en_set 0/1, or a position or velocity column), which clears the flag; the flag joins en_hash — brief "stays where it is until the game moves or removes it" — without the flag a flyer resting on a face would hit at t = 0 every tick and report a block hit each time.
Task 3: Ruling: the seen flag is the same flags byte (EN_F_SEEN), set each tick before movement from the position at the start of the tick: within the kind's seen distance of any focus horizontally (x and z), no hysteresis, no focus none; en_stat(1) is the count seen in the last tick — controller ruling (g) — Task 6 replaces the rule and adds events 3 and 4, which this task does not write.
Task 3: Ruling: en_tick's order: clear the event list; write the removals queued since the last tick; then kind by kind, each kind's dense array forward (a removal moves the kind's last entry into the hole, which is looked at next): age += dt, lifetime (removed when age > lifetime, reason 1, event 6 at its position, before it moves), seen flag, then flying movement (gravity into the velocity first, then the step) — controller rulings (a), (e), (f) — the design's tick order (all lifetimes, then all seen movement) is per entity here; with no interaction between entities yet the two orders give the same result.
Task 3: Ruling: every removal is event 6 (a the id, i0 the reason, the point its last position): one made inside en_tick goes into that tick's list; one made between ticks (the game's en_remove, reason 0) is queued with its id, reason and position copied, so the row can be reused at once, and written first by the next en_tick; the queue holds at most 65,536, the rest dropped and counted in stat 5 — the coordinator's correction to controller ruling (c) (a later task releases a removed entity's figure from it).
Task 3: Ruling: events are fixed records in two arrays allocated at open (65,536 x 7 int64: code, a, b, i0..i3; 65,536 x 3 doubles: x, y, z); en_events copies at most max and answers how many, or with a NULL array answers the count alone; past 65,536 a tick events are dropped and counted (stat 5, cumulative) — design "left to the builder" — en_x_tick and en_x_events carry them to March as a NativeIntArr and a NativeFloatArr (raw doubles at +32, as the runtime lays them out), a NativeFloatArr because the points are metres in a world 2 km across and 32-bit floats would lose a tenth of a millimetre there.
Task 3: Ruling: a dt negative or not finite is counted in stat 4 and the tick runs as dt 0 (events cleared, queued removals written, seen flags set, nothing ages or moves); a velocity that would leave a float's range under gravity, or a position that would stop being finite, is left as it was — Review Focus 2 — a tick of dt 0 is a way to read the seen state without moving anything.
Task 3: Ruling: `Strata.Stream.take_changed` is stored by replacing the Stream's ninth field (the unloads list) with a record `ChunkLog { sl_unloads, sl_changed, sl_dropped }`: `take_unloads` empties only sl_unloads, `take_changed` only the two sets; the sets are `Strata.Store.Store(Bool)` keyed by chunk, so each key appears once, a load removes it from the dropped set and an unload from the changed set; loads are logged where a generated chunk is inserted (apply_gens, through the existing Applied record, which gains the log), edits in `apply` (the outcome's dirty chunks that are loaded), unloads in drop_far — the task's "least invasive" instruction: no 11-field pattern changed, only the places that built or read the old list — an edit at a chunk border lists the neighbours its dirty list names, whose contents did not change; resending their masks is harmless. The brief's `Strata.Stream.adopt` is the existing `apply` (the voxel-core design calls it "adopts o's world").
Task 3: Ruling: `Strata.Entities.Event` is `EnEvent(code, a, b, i0, i1, i2, i3, x, y, z, block)`; `events` sizes a NativeIntArr and a NativeFloatArr from en_x_event_count, fills both in one call, and builds the list back to front; `ev_block` is read from the world given to `events` for a block hit and is -1 otherwise; `ev_voxel` is (0, 0, 0), `ev_face` and `ev_reason` -1 for events they do not belong to — controller ruling (d) — a world edited between the step and the read answers the new block.
Task 3: Ruling: the wrapper calls March makes only for their effect (block_table, chunk, chunk_uniform, chunk_drop, tick) answer an Int that the March side folds into a sum or a test, so no call is a Unit statement or bound to `_` (GAPS S9, S10) — none.
